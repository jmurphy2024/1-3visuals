## 📝 **R Script Formatting Guidelines**

To maintain consistency and readability across all R scripts in this project, adhere to the following formatting standards:

1.  **Script Header:**
    Every R script must begin with a comprehensive header block providing essential metadata. This header will be formatted with `##` for each line.

    ```R
    ## WD location: Where in the WD the script is located
    ## Script: your-script-name.R
    ## Purpose: A concise description of what the script accomplishes.
    ## Author: Your Name/Team Name
    ## Date Created: YYYY-MM-DD
    ## Last Modified: YYYY-MM-DD (Brief note on changes, if applicable)
    ## Dependencies: List of R packages required (e.g., readr, dplyr, ggplot2)
    ## Input: Path(s) to primary input data files.
    ## Output: Path(s) to primary output files generated by the script.
    ```

2.  **Hierarchical Sectioning:**
    Organize the script content into clearly defined, hierarchical sections using decimal notation and increasing equal signs, similar to the Phase 1 scripts. Each heading should concisely describe the subsequent code's purpose.

    * **Level 0: ABOUT (Special Case)**
        The very first section, providing the script header and initial setup details, should be `0. ABOUT`. It will not have preceding empty rows.
        ```R
        # ==== 0. ABOUT ====
	## WD location: 02_Scripts/Data_prep
        ## Script: data-clean-initial.R
        ## Purpose: Initial cleaning and preparation of raw data for exploratory analysis.
        ## Author: Your Name
        ## Date Created: 2025-08-18
        ## Last Modified: 2025-08-18
        ## Dependencies: readr, dplyr
        ## Input: 01_data/raw/source_data.csv
        ## Output: 01_data/processed/cleaned_data.RData

        # Load necessary libraries
        library(readr)
        library(dplyr)
        # ... other setup code ...
        ```
    * **Level 1 Heading:**
        These are major sections, all caps, preceded by two empty lines (after Level 0), and marked by four equal signs (`====`). These act as main sections in RStudio's document outline.
        ```R


        # ==== 1. DATA LOADING AND INITIAL CLEANING ====
        ```
    * **Level 2 Heading:**
        Subsections, marked by five equal signs (`=====`).
        ```R


        # ===== 1.1. Load Raw Data =====
        ```
    * **Level 3 Heading:**
        Further subdivisions, marked by six equal signs (`======`).
        ```R


        # ====== 1.1.1. Read CSV Files ======
        ```
    * **Level 4 Heading (and so on):**
        Continue adding an additional equal sign for each deeper level of heading as needed.
        ```R


        # ======= 1.1.1.1. Filter for Relevant Columns =======
        ```

3.  **Code Comments:**
    In addition to headers, use ample inline comments (`#`) to explain complex logic, choices, and non-obvious steps within the code blocks.

## 📊 1/3 Country Project: Comprehensive Overview

This document provides a comprehensive introduction to the "1/3 Country Project," outlining its core concept, detailed objectives for Phase 1, the strategic and technical direction for Phase 2, and the overall workflow. This detailed overview is designed to minimize clarifying questions when starting new discussions or collaborative sessions.

---

#### Project Name: **1/3 Country Project**

#### Overall Vision:
The "1/3 Country Project" transcends traditional national average analyses to provide a granular understanding of socioeconomic disparities within the United States. It reimagines the U.S. population as **three distinct "countries"** based on household income: the **Bottom Third (Low-Income)**, **Middle Third (Medium-Income)**, and **Top Third (High-Income)**. The fundamental purpose is to reveal the differential impacts of economic and social systems on these groups, thereby informing more equitable, targeted, and impactful science, technology, and innovation policy. This framework seeks to address "wicked problems" – complex, interconnected societal challenges – by linking basic research directly to inclusive solutions.

---

#### Phase 1: Foundational Analysis & Visualization

**Key Objectives & Methodology:**
* **Concept Operationalization:** Dr. Michael Crow's "1/3 Country Concept" was operationalized by precisely defining the three income-based "countries" using weighted household income data.
    * **Bottom Third (Low-Income):** Households with incomes from approximately **\$0 to \$64,400**. Characterized by economic stagnation, housing insecurity, and vulnerabilities in health, education, and infrastructure.
    * **Middle Third (Medium-Income):** Households with incomes from approximately **\$64,401 to \$130,000**. Experiences moderate stability but increasing susceptibility to economic shifts and declining civic engagement.
    * **Top Third (High-Income):** Households earning **\$130,001 and above**. Benefits from robust economic security, superior infrastructure, and strong civic participation.
* **Granular Analysis:** To enhance precision, each tercile was subdivided into 20 ventile groups, resulting in **60 granular income quantiles**. This allowed for detailed examination of indicator variations *within* and *between* the "countries." Income imputation (using CPS ASEC data) was applied to datasets with categorical income to ensure consistent assignment to these 60 bins.
* **Societal Domains:** Analysis was structured around three critical societal domains, each supported by foundational literature identifying income as a key determinant:
    1.  **Economic Security and Opportunity:** Assesses financial stability, employment, housing affordability, and upward mobility.
    2.  **Health and Human Development:** Focuses on healthcare access, quality of medical care, educational attainment, and overall well-being.
    3.  **Equity, Sustainability, and Community Resilience:** Examines civic engagement, infrastructure quality, environmental resilience, and access to essential resources.
* **Data Sources:** Primarily relied on publicly available data from:
    * **IPUMS ACS (American Community Survey):** For comprehensive demographic and socioeconomic data.
    * **CPS (Current Population Survey) supplements:** Including ASEC (Annual Social and Economic Supplement), FSS (Food Security Supplement), and Voting supplements.
    * **NHIS (National Health Interview Survey):** For health-related indicators.

**Key Findings & Output:**
Phase 1 culminated in the **"1/3 Country Reader"** and **"Indicators Across Incomes Presentation,"** which visually demonstrated significant disparities across all three domains. Notable visualizations included:
* **Average Household Income Per Ventile (e.g., Reader, Figure 1):** Clearly illustrated the non-linear distribution of wealth, with a steep curve in the Top Third.
* **Racial/Ethnic Proportion by Position in Income Distribution (e.g., Reader, Figure 3):** Showed increasing proportions of White, Non-Hispanic individuals in higher income brackets and higher proportions of Hispanic and Black, Non-Hispanic individuals in the Bottom Third.
* **Labor Force, Employment & Unemployment Rates (e.g., Reader, Figure 5):** Demonstrated a strong positive correlation between income and labor force participation/employment, and a sharp inverse correlation with unemployment.
* **Housing Cost Burden (e.g., Reader, Figure 13):** Highlighted severe housing cost burdens for renters in the Bottom Third.
* **Educational Attainment (e.g., Reader, Figure 9):** Showed a clear gradient where higher education attainment correlated strongly with higher income brackets.
* **Voter Turnout Rate (e.g., Reader, Figure 23):** Indicated a strong positive correlation between income and civic participation.

These outputs highlighted how national averages obscure the distinct realities faced by each income group, necessitating a reorientation of science policy to prioritize equitable outcomes.

#### Phase 2: Building a Robust & Reusable Framework

**Project Objective:**
Phase 2 aims to transition from a primarily analytical project to building a **robust, reusable system** for analyzing and visualizing socioeconomic data at scale. This involves:
1.  **Constructing a Comprehensive Geographic Income Database:** Creating a single, reliable reference dataset containing demographic and estimated median household income data for a wide range of U.S. geographic levels (e.g., state, county, tract, block group, cty\_sub, place, sd\_elm, sd\_sec, sd\_uni, puma, cbsa, urb\_area, zcta). This database will also include advanced estimation for missing values.
2.  **Developing a Modular R-based Framework:** Refactoring the existing (monolithic) Phase 1 analysis script into a modular, reusable framework that strictly separates core logic from data-specific tasks. This allows for rapid, standardized analysis and visualization of new datasets by other team members.

**Key Stages & Deliverables:**

* **STAGE I: Constructing the Geographic Region Income Database:**
    * **Goal:** To produce a high-quality `geographic_income_database.rds` file.
    * **Methodology:**
        * **Data Collection (IPUMS NHGIS & ACS Microdata):** Uses the IPUMS API to download 2019-2023 5-year ACS summary tables (B19013 for Median Household Income, B19001 for Income Distribution Brackets) across specified geographic levels. It also acquires individual-level microdata (HHINCOME, HHWT, PUMA) from IPUMS ACS to serve as the "source of truth" for income estimation.
        * **Advanced Income Estimation:** Calculates PUMA-level median incomes by bracket from microdata and creates a lookup table. For areas with missing, negative, zero, or top-coded medians (>\$250,001), it imputes the median income by identifying the income bracket containing the 50th percentile and using the pre-calculated median from that area's PUMA-bracket lookup table.
        * **Harmonization:** Combines downloaded CSV files into a master data frame, ensuring consistent naming and types, and adding top-level geographic identifiers.
* **STAGE II: Creating Shared Functions R Scripts:**
    * **Goal:** To refactor core framework logic into reusable R functions.
    * **Deliverable:** Two R scripts containing only functions:
        * `shared_visuals.R`: Will contain functions for the visual structure (e.g., `setup_tercile_plot_background()` for colored backgrounds and labels, `calculate_income_bins()` for the 60 bin boundaries, `create_final_plot()` for generating visualizations).
        * `income_utils.R`: Will contain utility functions, such as `add_income_estimates(my_data, geography_column)` to join user data with the `geographic_income_database`.
    * **Refactoring Approach:** Parts of the Phase 1 script's logic will be integrated into these new functions, potentially through manual copying, rewriting, or direct translation of existing code. The aim is for `create_final_plot()` to be a flexible wrapper capable of generating various plot types based on parameters.
* **STAGE III: Creating Data Preparation Templates:**
    * **Goal:** To streamline the process of preparing new datasets for visualization using standardized, "plug-and-play" templates.
    * **Deliverable:** A single, well-documented template script (`template_data_prep.R`) and a folder of completed data preparation scripts as proof-of-concept.
    * **Structure of `template_data_prep.R`:** Will have clearly defined, user-configurable sections:
        * `SETUP`: Load libraries and source shared function scripts.
        * `USER INPUTS`: Specify parameters (raw data path, geography column, variable to plot, success/failure coding).
        * `DATA LOADING`: Code to load raw dataset.
        * `INCOME ESTIMATION`: Call to `add_income_estimates()` from Stage II.
        * `VARIABLE CALCULATION`: Logic for calculating the final y-axis variable.
        * `FINAL PREPARATION`: Format data for visualization functions.
        * `VISUALIZATION`: Call to `create_final_plot()` from Stage II.
    * **Workflow for New Indicators:** The process will be: acquire raw data, copy `template_data_prep.R`, fill in `USER INPUTS` and `VARIABLE CALCULATION`, and then run the script.

**Key Deliverables & Future Directions for Phase 2:**
* A clean, high-quality **`geographic_income_database.rds`** file.
* Modular R scripts (`shared_visuals.R`, `income_utils.R`) containing reusable functions.
* A well-documented template (`template_data_prep.R`) and examples for standardized data preparation scripts.
* Enabling **temporal analysis** (tracking changes over time) and **geographic analysis** (mapping spatial disparities) at granular levels, leveraging the new database and framework. This also sets the foundation for a synthesized model with hundreds of indicators.
