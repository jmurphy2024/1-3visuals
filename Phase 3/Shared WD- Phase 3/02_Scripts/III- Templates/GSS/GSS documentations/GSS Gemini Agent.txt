The Core Problem (Leading to Blank Plot)

The user is getting a blank plot because of a data mismatch, which we diagnosed using console output:
	•	The Viz Script is (correctly) using ACS dollar cutoffs (e.g., $64,000) for grouping.
	•	The Prepare Script is passing the original GSS income16 variable, which contains category codes (1-26), not dollar values.
	•	Result: When the viz script compares the codes (1-26) to the dollar cutoffs (~64k, ~100k, etc.), all 3,000+ respondents fall into the very first bin (T1-G01). The summary_stats_grouped data frame has only one row, so ggplot cannot draw a line.

The Agreed-Upon Solution (Hot-Deck Imputation)

To solve this, the user wants to impute a continuous dollar value for each GSS respondent.
We agreed the prepare.R script must be modified to perform a hot-deck imputation. This involves:
	1	Loading an ASEC donor file (which has continuous income) in addition to the GSS data.
	2	Defining the GSS income16 category ranges (e.g., 18 = $40,000 to $50,000).
	3	For each GSS respondent, randomly sampling a real, inflation-adjusted dollar value (HHINCOME_ADJ) from an ASEC respondent within the same income bracket, using ASEC weights (asecwt) as the probability.
	4	Saving this new continuous variable as hhincome_imp (lowercase) in the prepared_GSS2024_Happiness.rds file.
The viz.R script must then be updated to use this new hhincome_imp variable (instead of income16) as the input for the assign_income_groups function. This will allow for a correct, dollars-to-dollars comparison against the ACS quantile cutoffs.
